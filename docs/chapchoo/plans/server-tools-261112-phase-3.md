## Fixed interfaces and presentation

- Use phase 1's protected Messages/ReadMessage contracts and repository message IDs. Receipt order and finite `through` bound are independent of native source ordinals. Browser transport uses canonical int64 strings; body reads keep the existing 32-KiB chunk and complete-byte assembly/final authority checks without lowering the user-input text limit.
- Server-render the initial admitted message region and hydrate exactly that state. Continue with one coalesced visible-document read owner, exact older anchors, truthful read errors and preserved reading position. A missing authorized body is explicit, never substituted or interpreted as an empty successful message.
- Retain input delivery/recovery/deletion, exact responder answers and Stop. Message provenance supports only current acknowledgement correlation; it is not permanent input recovery/deduplication or native replay authority. Temporary/pending input state must not become a second accepted user chat message.
- Keep native record reads for their real full-history/activity/request/plan consumers. Remove general native body/tool-field reads used solely to discover/filter primary-chat messages. Do not weaken the authorized live form/permission surface to obtain that separation.
- Reuse ConversationRecordDisclosure and ToolRecordDetails. User rows use a user icon; intentional publication uses a paper plane; ordinary native/model text uses a text icon and an Output label without the Agent name. Remove visible sender-name labels from full-record message rows, retain accessible role semantics, and use the current scoped primary theme color for their rail.
- Both user and publication collapsed rows use normalized body beginnings with existing one-line truncation. Publication classification uses the actual normalized tool name, not title/body resemblance or generic `other`; original captured tool input/output remains inspectable. Existing normalization retains ACP tool `name` and complete structured MCP input independently from display titles/kinds. The pinned MCP reporter supplies `server`, `tool` and `arguments` in that input (it does not currently emit a separate ACP `name`); decode that actual structured identity rather than inferring from its `mcp.*` title or inventing records.
